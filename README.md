# skill

个人常用指令库，用于集中保存和维护写作、科研绘图、GitHub 推送及日常工作中的可复用指令。

## 指令分类

| 分类 | 内容 | 建议存放位置 |
| --- | --- | --- |
| 写作 | 论文撰写与修改、中英文翻译、图例、投稿信、审稿回复 | `writing/` |
| 绘图 | 科研图片排版、字体与线条规范、配色、热图、通路图、SVG 图标 | `plotting/` |
| GitHub 推送 | 文件上传、README 更新、提交整理、版本发布与页面更新 | `github/` |
| 日常整理 | 文件命名、格式转换、资料归档及重复性任务 | `routine/` |

以上为后续整理指令时使用的分类，具体指令将逐步补充。

## 使用方式

1. 每条独立指令保存为一个 Markdown 文件，文件名应说明用途。
2. 使用时复制相应指令，并补充本次任务的文件、目标、参数及输出位置。
3. 对经常重复的要求持续修订，保留适用范围和必要的例外说明。

## 指令记录格式

每条指令建议包含：

- **用途**：适用于什么任务。
- **输入**：需要提供的文件、数据或背景信息。
- **指令正文**：可以直接复制使用的完整要求。
- **输出要求**：文件格式、命名、排版或提交方式。
- **检查要点**：完成后需要核对的内容。

## 维护原则

- 指令以清晰、具体、可复用为主，项目特定信息在使用时补充。
- 写作指令应保留原始数据、研究结果与引用的真实性。
- 绘图指令应明确尺寸、字体、字号、线宽、颜色及可编辑性。
- GitHub 操作指令应明确账号、仓库、分支和本次修改范围；保存的指令不代表已经执行相应操作。
- 不在仓库中保存密码、访问令牌或其他凭据。
